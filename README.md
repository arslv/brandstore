# QLIC

> До 07.11.2026 проект назывался Brand Store. Внутренние имена (папка и служба `brandstore`, репозиторий, база `brandstore.db`) остались прежними.

Маркетплейс покупок в магазинах Португалии с доставкой в Россию. Покупатель выбирает магазин, вставляет ссылку на товар, указывает размер, цвет и цену в евро и сразу видит цену в рублях. Заказ приходит на почту магазина и в админку.

Стек: Node.js 22.13+, Express, SQLite, EJS. База данных встроена в Node.js (`node:sqlite`): ничего не нужно компилировать и отдельно устанавливать. Всё хранится в файле `data/brandstore.db`.

## Запуск на своём компьютере

Нужен Node.js версии 22.13 или новее — версия LTS с [nodejs.org](https://nodejs.org).

Проще всего двойным кликом:
- **Windows** — `start-windows.bat`
- **Mac** — `start-mac.command` (при первом запуске: правый клик → «Открыть»)

Файл сам установит зависимости, запустит сайт и откроет http://localhost:3000. Чтобы остановить сайт, закройте окно.

Или вручную в терминале, из папки проекта:

```bash
npm install
npm start                 # http://localhost:3000
```

Файл `.env` для запуска на своём компьютере не нужен. Он понадобится на сервере: `cp .env.example .env` и заполните адрес сайта, пароль админа, почту. Не включайте `NODE_ENV=production` при работе через `http://localhost` — вход в аккаунт перестанет работать.

Если порт 3000 занят, запустите на другом: `PORT=4000 npm start` (Mac/Linux) или `$env:PORT=4000; npm start` (PowerShell).

При первом запуске создаются администратор (из `.env`) и 211 магазинов. Если база уже есть от прошлой версии, она обновится сама при запуске.

Админка: `/admin`, вход — `ADMIN_EMAIL` / `ADMIN_PASSWORD` из `.env`.

Иконки магазинов подгружаются автоматически по домену. Чтобы хранить их на своём сервере (быстрее и без внешних сервисов), один раз выполните на сервере с интернетом:

```bash
npm run icons
```

Для магазинов, у которых иконка мелкая или не нашлась, показывается монограмма. Свой логотип можно загрузить в «Админка → Магазины».

## Как устроено

**Покупатель.** Каталог магазинов (A–Z, поиск, категории), страница магазина со ссылкой на его португальский сайт, заказ по ссылке (размер, цвет, количество, фото, комментарий), корзина, регистрация, **баланс** (пополнение на любую сумму, история), оформление с оплатой с баланса, личный кабинет со статусом заказа и трек-номером.

**Главная.** Вкладки **Женщинам / Мужчинам / Детям / Для дома / Косметика** в шапке, под ними — почти во всю ширину экрана плитки брендов выбранной вкладки (с острыми углами, вплотную, как таблица): фон в цвет подложки логотипа, название на всю плитку. Высота плиток подстраивается под экран: видно 2 ряда, третий растворяется, и кнопка «Ещё бренды» видна без прокрутки (на телефоне 3 ряда + 1). Кнопка раскрывает остальные плитки вкладки, после этого ведёт на страницу всех брендов. Ниже — «Вставьте ссылку на товар»: покупатель вставляет ссылку, сайт подтягивает цену, фото и размеры, покупатель выбирает размер и цвет и жмёт «Добавить в корзину», не уходя со страницы. Фото и комментарий — в полной форме «Заказ по ссылке».

**Страница магазина.** Кнопка «Открыть сайт …» и сразу та же форма «Вставьте ссылку на товар»: покупатель вернулся с сайта магазина и вставляет ссылку здесь же. Если ссылка верная — в поле появляется зелёная галочка, без лишнего текста.

Вид плитки — «Админка → Магазины → магазин → Плитка на главной»: надпись (как в логотипе, например MANGO), цвет фона, цвет надписи и шрифт, с превью. Для ~30 известных брендов цвета уже заданы. Фирменные шрифты брендов закрытые и платные, поэтому используются свободные шрифты похожего характера: контрастный с засечками (как у Zara), курсив, геометрический (как у Mango), жирный (как у adidas).

Какие бренды на какой вкладке и в каком порядке — «Админка → Магазины → магазин → На главной»: галочки вкладок и номер места (1 — первым; без номера — после пронумерованных, по алфавиту). «Главная без вкладки» — то, что видно на главной, пока вкладка не выбрана.

**Только по ссылке.** Витрины товаров, карточек товаров и избранного нет (убраны 07.11.2026): покупатель выбирает товар на сайте магазина и вставляет ссылку. Поиск в шапке ищет бренды.

**Только магазины из списка.** Заказать можно только из магазинов, которые есть на странице «Бренды». Ссылку с другого сайта форма не принимает и подсказывает выбрать магазин из списка. Чтобы принимать заказы из нового магазина, добавьте его в «Админка → Магазины».

**Проверка португальской версии.** У каждого магазина есть «префикс PT» — например `zara.com/pt`. Если покупатель вставляет ссылку с другой версии сайта, форма подсказывает открыть португальский сайт, а в заказе такая позиция помечается для менеджера.

**Цены.** Цена в евро × курс ЦБ × (1 + наценка), округление вверх до 10 ₽. Наценка — **15%**. Оплата в рублях. В оформленном заказе курс и наценка фиксируются.

**Доставка в Россию — 50 € за заказ**, от количества товаров не зависит (под кнопкой «Оформить заказ» так и написано). В рубли — по текущему курсу, без наценки. Если в заказе 1–2 товара, в корзине и при оформлении покупатель видит: «Заказ из 1–2 товаров может доставляться дольше обычного». Наценка, доставка в евро и ручной курс меняются в «Настройки»; в конкретном заказе менеджер может поправить доставку вручную.

**Заказ.** (номера — QL-100001 и далее). Проверки наличия перед оплатой нет — покупатель смотрит наличие на сайте магазина сам.
1. Покупатель оформляет заказ — сумма сразу списывается с баланса, заказ «Оплачен». Не хватает денег — кнопка «Пополнить на N ₽» ведёт на пополнение ровно на недостающую сумму и возвращает к оформлению с заполненной формой.
2. Письма: магазину — «Новый заказ … — оплачен», покупателю — «Заказ … оплачен».
3. Менеджер выкупает товары (удобно по разделу «По магазинам»). Закончился товар — кнопка «Нет в наличии» в заказе: его стоимость возвращается на баланс покупателя, ему приходит письмо. Если в заказе ничего не осталось — заказ отменяется и возвращается всё, включая доставку.
4. «Отправлен» — только с трек-номером (покупатель получает его в письме), затем «Доставлен». «Отменён» — вся оставшаяся сумма возвращается на баланс.

Покупатель видит только: «Оплачен» → «Отправлен» (трек) → «Доставлен». Заказы, оформленные до перехода на баланс и не оплаченные, показываются как «Ожидает оплаты» — их можно оплатить с баланса из личного кабинета.

Позиции дороже порога из настроек (по умолчанию 300 €) подсвечиваются в заказе: для таких товаров действуют ограничения ЕС на отправку в РФ.

## Цена по ссылке автоматически

Когда покупатель вставляет ссылку на товар, сайт сам подставляет цену в евро, название, фото, размеры и цвета. Покупатель может поправить цену, а в заказе у позиции видно, откуда она: «цена с сайта» или «цена от покупателя».

Как это работает (`src/lib/parser.js`):
1. **Быстрый запрос** (доли секунды) — сайт просто скачивает страницу.
2. **Встроенный Chrome** (`src/lib/browser.js`) — если магазин не отдал страницу (защита от ботов у Zara, Adidas и т. п.) или цена появляется только после скриптов, страница открывается в Chrome без окна, как у обычного посетителя. Занимает 3–15 секунд.

На каждом шаге цена ищется так: данные магазина (сейчас — Adidas и магазины Inditex: Massimo Dutti, Pull&Bear, Stradivarius — с размерами и наличием), Shopify, разметка товара для поисковиков (JSON-LD), мета-теги, микроразметка и **теги из настроек магазина**.

**Теги магазина.** В «Админка → Магазины → магазин» есть поля «Цена», «Старая цена», «Название», «Фото», «Размеры». Откройте товар в Chrome, нажмите правой кнопкой на цену → «Просмотреть код», возьмите класс элемента и впишите с точкой, например `.money-amount__main`. Чтобы взять атрибут — `meta[property="og:image"]@content`. Несколько вариантов — через `||`. Там же есть «Проверить ссылку»: показывает, что удалось взять и на каком шаге. Для Zara теги уже заполнены (заготовка — проверьте).

**Установка Chrome:** `start-windows.bat` / `start-mac.command` скачивают его сами (один раз, около 150 МБ). Вручную: `npm run browser`. Без него работает только быстрый шаг.

**Проверка из терминала:** `npm run check -- "ссылка на товар"` — покажет каждый шаг (ответ магазина, заголовок страницы, где нашлась цена) и результат.

Если сайт работает на сервере в России, часть магазинов может не пускать его совсем — это видно в проверке как «Access Denied» на обоих шагах. Тогда укажите в `.env` прокси в ЕС: `PARSER_PROXY=http://логин:пароль@адрес:порт` — он используется и для быстрого запроса, и для Chrome. На сервере Chrome занимает около 300–500 МБ памяти и закрывается сам после 3 минут простоя.

**Сайты со строгой защитой (Adidas).** Встроенный Chrome они распознают. Тогда в `.env`:

```
PARSER_BROWSER_CHANNEL=msedge
PARSER_BROWSER_WINDOW=on
```

Страницы открываются в установленном Edge (`chrome` — в Google Chrome) через Patchright — версию Playwright, которую защиты не замечают, с окном за пределами экрана (`visible` — окно видно). Так Adidas отдаёт цену за 3–4 секунды (с VPN в ЕС). Куки защиты сохраняются в `data/browser-profile`, и магазины видят «постоянного посетителя»; если товар всё же ответил отказом, браузер сначала заходит на главную магазина и пробует снова (так пускают H&M и Farfetch). Если что-то пошло не так — профиль можно просто удалить, он создастся заново. Окно требует рабочего стола: на сервере без экрана так не получится — там нужен отдельный вариант (виртуальный экран).

Тесты: `npm test` (быстрый шаг и встроенный Chrome на имитации защищённых магазинов, вкладки главной, баланс и возвраты).

## Почта

Заполните SMTP в `.env` (подойдёт Яндекс 360, Mail.ru для бизнеса, Unisender Go и др.). Пока SMTP не настроен, письма сохраняются в `data/outbox` — их можно открыть в браузере. Проверка: «Настройки → Отправить тестовое письмо».

## Баланс и оплата

Заказы оплачиваются **с баланса**. Покупатель пополняет баланс на любую сумму от 100 ₽ (страница «Баланс» в личном кабинете, сумма видна в шапке): быстрые суммы 1 000 / 3 000 / 5 000 / 10 000 ₽, способ — карта, СБП, SberPay, T-Pay, ЮMoney (набор — «Настройки → Пополнение баланса»). Там же история: пополнения, оплаты заказов, возвраты.

Как пополняется баланс («Настройки → Пополнение баланса»):
- **Тестовый режим** (по умолчанию) — тестовая страница банка, деньги не списываются, баланс пополняется сразу. Для проверки всего пути.
- **Перевод по реквизитам** — покупатель создаёт заявку и видит текст из настроек; когда деньги пришли, менеджер жмёт «Зачислить» в «Админка → Балансы» (покупателю приходит письмо).
- **ЮKassa** — настоящая оплата. Укажите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в `.env`, в кабинете ЮKassa пропишите адрес уведомлений `https://qlic.store/webhooks/yookassa` (событие `payment.succeeded` и `payment.canceled`). Баланс пополняется сам, когда ЮKassa подтвердит платёж.

**Чеки (54-ФЗ)** — `YOOKASSA_SEND_RECEIPT=true` (нужны «Чеки от ЮKassa» или своя онлайн-касса, подключённая к ЮKassa). Пополнение баланса — это аванс, поэтому чеков два: при пополнении — «аванс» (отправляет ЮKassa вместе с платежом), при оплате заказа — «полный расчёт» с зачётом аванса (сайт отправляет сам, по каждому пополнению, из которого оплачен заказ). Если второй чек не отправился, в истории заказа в админке появится запись — его можно сформировать в кабинете ЮKassa. Какие признаки ставить в чеках (агентская схема, НДС) — уточните у бухгалтера.

**Возврат денег с баланса на карту.** Покупатель пишет вам. Сделайте возврат платежа в кабинете ЮKassa (чек возврата ЮKassa отправит сама), затем в «Админка → Балансы → покупатель» спишите эту сумму с комментарием «Возврат на карту».

**Админка → Балансы**: заявки на перевод по реквизитам, все операции, у каждого покупателя — баланс, история и ручная корректировка (зачислить / списать, с комментарием, который увидит покупатель). В «Покупатели» — колонка «Баланс».

## Размещение на сервере

**Быстро, рядом с другими проектами на сервере** (ничего чужого не трогает: свой Node.js, свой порт от 3100, своя служба `brandstore`; nginx и системный Node не меняются). На сервере от root:

```bash
curl -fsSL https://raw.githubusercontent.com/arslv/brandstore/main/deploy/install.sh | bash
```

В конце скрипт покажет адрес сайта (`http://IP:3100`) и пароль админки. Обновить сайт до последней версии с GitHub — та же команда. Журнал: `journalctl -u brandstore -n 50`. Сменить пароль админа:

```bash
cd /opt/brandstore && sudo -u brandstore -H env PATH=/opt/brandstore/.node/bin:$PATH npm run admin-password
```

**Отдельный сервер только под сайт** (с nginx, HTTPS и доменом). **Сервер:** VPS в России (данные покупателей по 152-ФЗ хранятся в РФ) — Timeweb Cloud, Selectel и т. п., Ubuntu 24.04, 2 ядра, 4 ГБ памяти. При создании вставьте открытый SSH-ключ из файла `~/.ssh/brandstore_ed25519.pub`.

В `.env` на своём компьютере допишите адрес сервера:

```
DEPLOY_HOST=root@адрес-сервера
```

Всё остальное — одной командой с этого компьютера:

| Команда | Что делает |
|---|---|
| `npm run deploy -- --setup` | первый раз: ставит Node.js, Google Chrome, виртуальный экран, nginx, автозапуск, ночные копии базы, брандмауэр |
| `npm run deploy -- --data` | переносит базу и фото с этого компьютера (только если на сервере базы ещё нет) |
| `npm run deploy` | выкладывает последнюю версию (последний коммит git) и перезапускает сайт |
| `npm run deploy -- --domain brandstore.ru --email вы@почта.ru` | подключает домен и бесплатный HTTPS |
| `npm run deploy -- --proxy "http://логин:пароль@адрес:порт"` | прокси в ЕС для цен по ссылке |
| `npm run deploy -- --check "ссылка"` | проверяет цену по ссылке на сервере |
| `npm run deploy -- --logs` | журнал сайта |

**Смена пароля админа** (обязательно перед запуском — по умолчанию `admin12345`). На сервере:

```bash
ssh -t -i ~/.ssh/brandstore_ed25519 root@адрес-сервера "cd /opt/brandstore && sudo -u brandstore -H npm run admin-password"
```

На своём компьютере — просто `npm run admin-password`.

Как устроено на сервере: сайт в `/opt/brandstore`, запускается службой `brandstore` (systemd) от отдельного пользователя; цены по ссылке — Google Chrome с окном на виртуальном экране (служба `brandstore-xvfb`); nginx принимает запросы на 80/443. Копии базы и фото — каждую ночь в `/var/backups/brandstore`, 14 дней. Это копии на том же сервере — раз в неделю стоит скачивать их к себе.

## Структура

```
server.js                 точка входа
src/data/stores.js        список магазинов (используется при первом запуске)
src/routes/               страницы: главная и бренды, вход, корзина, баланс и заказы, админка
src/services/             корзина, заказы
src/lib/                  цены, курс ЦБ, почта, ЮKassa, проверка ссылок
views/                    шаблоны страниц (EJS)
public/css, public/js     стили и скрипты
scripts/fetch-icons.js    загрузка иконок магазинов
start-windows.bat         запуск двойным кликом на Windows
start-mac.command         запуск двойным кликом на Mac
```

## Домен и HTTPS

Домен **qlic.store** (reg.ru). Подключение:
1. reg.ru → домен → «DNS-серверы и управление зоной» → «Изменить»: A-записи `@` и `www` → IP сервера (161.104.55.191). Подождать 15–60 минут.
2. На сервере от root:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/arslv/brandstore/main/deploy/domain.sh | bash -s -- qlic.store
   ```
   Скрипт проверит DNS, добавит в nginx отдельный сайт для домена (другие проекты не трогает; если порты 80/443 заняты не nginx — остановится и ничего не изменит), получит бесплатный сертификат Let's Encrypt (продлевается сам), пропишет `SITE_URL=https://qlic.store` и перезапустит сайт. После этого входить только через https://qlic.store.

## Документы и реквизиты

Страницы: `/offer` (публичная оферта), `/privacy` (политика обработки персональных данных), `/consent` (согласие на обработку ПДн — отдельный документ, как требует 152-ФЗ с 01.09.2025). Ссылки — в подвале. Реквизиты (ИП/ООО, ОГРН, ИНН, адрес) заполняются в «Админка → Настройки → Реквизиты продавца» и сами подставляются в документы и подвал; пока не заполнены, в документах видны жёлтые пометки, а в сводке админки — предупреждение.

При регистрации — галочка «Даю согласие на обработку персональных данных», при оформлении — две отдельные: оферта и согласие. Время и редакция документов сохраняются у пользователя и в заказе.

Тексты — шаблон, их стоит показать юристу. Кроме сайта по закону нужно: зарегистрировать ИП/ООО, подать уведомление в Роскомнадзор об обработке персональных данных (pd.rkn.gov.ru) до начала работы, хранить базу на сервере в России.

## По магазинам (админка)

«Админка → По магазинам»: товары оплаченных заказов, собранные по магазину, а внутри — по покупателю (например, ZARA: 3 товара у одного, 2 у другого) — удобно выкупать одной корзиной. У каждого заказа рядом со статусом — адрес доставки и способ (пункт выдачи или курьер). Вкладки: «Оплачены» (к выкупу) и «Отправлены». Когда заказ отправлен с трек-номером, он уходит из «Оплачены». Отметок «выкуплен» нет — покупатель видит только «Оплачен → Отправлен → Доставлен».
